# Security Policy

## Supported version

Security fixes are targeted at the latest Community Edition release.

## Reporting a vulnerability

Please use the GitHub repository's **Security** tab and private vulnerability reporting / Security Advisories when available. Do not disclose an unpatched vulnerability publicly before a reasonable remediation period.

Do **not** post API keys, passwords, access tokens, private keys, real EML files, personal information, confidential attachments, company-internal paths, or other secrets in a public Issue. Create a sanitized reproduction using dummy values such as `example@example.com` and `C:\Example\...`.

If private reporting is not enabled for the repository, open a public Issue containing only non-sensitive metadata and ask the maintainer to provide a private reporting channel; do not attach sensitive samples.
